# Engine patches

Fixes to Godot itself that the built binaries carry. They are applied by
`scripts/build.sh` before compiling, so every binary this repo publishes has
them. Each is upstreamable and none touches the Box3D module.

| Patch | Fixes |
|-------|-------|
| `scene_glsl_directional_ubo.patch` | `DirectionalLightData` ends in a `mediump vec3 pad`, which std140 aligns differently than the C++ struct expects. Strict GLES3 implementations (WebGL 2) then read the directional light data shifted. Three scalar floats pad the block the way std140 actually lays it out. |
| `dir_access_jandroid_make_dir_recursive_idempotent.patch` | `DirAccessJAndroid::make_dir_recursive()` returned `ERR_ALREADY_EXISTS` for a directory that exists, unlike the generic `DirAccess` it overrides. That disabled `ShaderCacheGLES3` on every Android run after the first. |
| `gles3_async_compile_queue_fallback.patch` | Asynchronous shader compilation via the secondary context (`shader_compilation_mode` 1 and 2) had no way out of a failure. The queue thread reported a failed build as *in progress*, so the variant stayed in `COMPILE_STATUS_PROCESSING_AT_QUEUE` forever, never freed its compile slot, and `INFO_SHADER_COMPILES_IN_FRAME` never returned to zero; a binary the main context refused at link time was parked in `COMPILE_STATUS_ERROR` for the session. Both now fall back to compiling that variant synchronously in the main context, which is what Adreno needs for the ubershader (*Sampler location or component exceeds max allowed*). `ShaderCacheGLES3::store()` also writes to a temporary and renames, so a run interrupted mid-write no longer leaves the empty file the next run reports as corrupted. |
| `gles3_ubershader_sampler_budget.patch` | The scene ubershader declared 12 sampler uniforms, and the engine takes texture image units from the top (`texunit:-N` resolves to `max_image_units - N`), so on a 16-unit mobile GPU it held units 3-14 and left the material **three**. A `SpatialMaterial` with albedo + normal + ORM + AO + emission needs five or six, and Adreno rejects the link with *Sampler location or component exceeds max allowed* — the ubershader never linked, which is the whole point of asynchronous compilation. Two of those declarations were avoidable: `//ubershader-skip` deletes the guard line rather than the block, so both halves of every mutually exclusive pair were declared at once. `USE_RADIANCE_MAP_ARRAY` is settled for the session by `texture_array_reflections`, so it becomes the compile-time `RADIANCE_MAP_ARRAY_AVAILABLE` and only one radiance sampler exists (one fewer conditional, so half the variants on that axis too); the GI probe samplers go behind the new `rendering/quality/gi_probes/enabled`, which a project with no GIProbe turns off. Engine 12 → 9 units, material 3 → 7. |
| `gles3_async_compilation_runtime_toggle.patch` | `shader_compilation_mode` is read once at startup, but the ubershader is only worth its cost where something is covering the screen. Building one costs about 0.8 s on an Adreno 618, and a cold boot to Odisea's menu built twenty-six of them -- 21 s of a frozen screen for a menu that has nothing to hide behind. `VisualServer.set_shader_async_compilation_enabled(bool)` flips `ShaderGLES3::max_simultaneous_compiles` between zero and the configured value, which is all `is_async_compilation_supported()` reads; the on-disk cache hangs off `shader_cache` and is untouched. `rendering/gles3/shaders/async_compilation_starts_enabled` (default true) lets a project boot with it asleep. Measured: menu 23.8 s → 1.45 s. |
| `dynamic_font_outline_advance_atlas_leak.patch` | A `DynamicFont` with `outline_size > 0` leaked on every redraw. For a character with no outline glyph (a space, or any glyph the stroker leaves empty) `DynamicFontAtSize::draw_char()` rendered the plain glyph through `_bitmap_to_character()` just to read its advance, and that packs the bitmap into the font atlas again each time, so the textures grew without bound. It now reads the advance straight from the loaded glyph. Measured in Odisea (Workbench, outline 1, a battery bar of `█░`): 4.8 KiB per redraw, about 280 KiB/s with one label repainting each physics frame. |
| `frt_platform_hooks.patch` | Godot 3.6 has no knowledge of FRT (`efornara/frt`), the out-of-tree SDL2 platform that PortMaster handhelds need -- ROCKNIX ships a stub `libGL.so.1`, so the `x11` template cannot start there. Six one-line hooks teach the build about `platform=frt`: the zstd asm list, the SDL2 controller-mapping guard, and the two libvpx/webm arm32 exclusions. The only real code is in `rasterizer_gles2.cpp`, where `eglGetProcAddress` becomes `SDL_GL_GetProcAddress` under `FRT_ENABLED`. Every hunk is inert unless `platform=frt`, so the other targets are unaffected. |
| `ios_joypad_rumble.patch` | `Input.start_joy_vibration()` did nothing on iOS: `JoypadIPhone` never read the vibration state. It now plays each request on the controller through `GCController.haptics` (iOS 14+; the template targets 15) as one continuous Core Haptics event -- intensity is the stronger of the two magnitudes, sharpness the share of the weak motor -- replaced by the next request and stopped by zero magnitudes or `stop_joy_vibration()`. `OSIPhone::iterate()` polls it once per frame, like the other platforms' joypad loops. |
| `android_joypad_rumble.patch` | Same gap on Android, where the rumble reached neither the controller nor anything else. `GodotLib.step()` hands each new vibration request to `Godot.vibrateJoypad()`, which finds the `InputDevice` behind the Godot joy id and plays it with the new `JoypadVibrator`: on Android 12+ through the device's `VibratorManager` (strong magnitude on the first motor, weak on the second when the pad has two), below that on `InputDevice.getVibrator()` with the stronger magnitude. Duration 0 holds for 60 s, as "until stopped". |
| `javascript_gamepad_rumble.patch` | Same gap on the web. `process_joypads()` sends each new request to `navigator.getGamepads()[i].vibrationActuator.playEffect("dual-rumble")` (Chromium and Firefox; browsers cap one effect at 5 s, which is also what duration 0 becomes), and zero magnitudes call `reset()`. Pads or browsers without an actuator are left alone. |
| `frt/sdl_rumble_motor_order.patch` | Applied to the FRT checkout, not to Godot. FRT already rumbled through `SDL_JoystickRumble`, but passed Godot's weak magnitude as SDL's low-frequency motor, which is the big strong one: the two motors were swapped. |
| `frt/sdl_hidden_window.patch` | Applied to the FRT checkout, not to Godot. Implements `--no-window`: FRT had no handler for it, so every headless run opened a real window. Like the x11 platform, the SDL2 window is still created (the GL context needs its surface) but created `SDL_WINDOW_HIDDEN` instead of shown, and the minimize/maximize setters early-return, mirroring `OS_X11`. This is what lets `scripts/test.sh` run against the FRT binaries. |

Origin: the first two come from the Odisea game project
(`src/tools/godot_web_template/`, `src/tools/godot_android_template/`), which
carried them locally against Godot 3.6.
